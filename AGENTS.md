# Working on the simplified-English Plurality

This branch carries the simplified-English edition of *Plurality: The Future of
Collaborative Technology and Democracy*. The job is to bring all 35 chapters of the English
book through one stage: adapting them to a reader with a different education and a
different field of experience from the one the American original assumed.

This file is the single source of truth for both people and AI assistants on this branch.
Tool-specific files (`CLAUDE.md`, `.cursor/rules/`, `.continue/rules/`,
`.github/copilot-instructions.md`) are one-line pointers here — never copies. Edit this
file; the pointers follow automatically.

## The edition

    contents/english/             the upstream book, read-only in this fork
      ↓  simplify — adapt to the reader's education and vocabulary
    contents/simplified-english/  this edition

There is a second stage, on the `norwegian` branch, which adapts this edition to Norwegian
Bokmål. It is not worked here, but it is why several rules below exist: this text is read
as a book *and* translated from, and a term left unexplained here is never explained.

The reader is a demographic, not a language: a 45-year-old with a master's in a social
science, fluent in institutions and without notation, described in full in
`docs/translation/audience.md`. Neither stage is a compression pass. The goal is
accessibility, and a paragraph that explains a term the reader lacks is longer than one
that assumed it.

**Both content layers use the exact same filenames.** `3-2-connected-society.md` is the
same chapter in each.

## One chapter, one branch, one pull request

The book is worked in parallel. Every job is a single chapter:

    simplify/3-2     from this branch, edits only contents/simplified-english/3-2-connected-society.md

To see everything that can be started right now:

```bash
vp run translation:next
```

Every job depends only on `contents/english/`, so all of them can run at once. There are no
chapter-to-chapter dependencies, because the shared decisions that would create them are
resolved up front in the registries.

### Files a chapter branch may change

- its one output file under `contents/simplified-english/`
- `translation/proposals/<chapter-id>.tsv`, to propose terms the glossary lacks

### Files a chapter branch must not change

- `contents/english/` — upstream text; fixes go to the upstream repository
- `translation/glossary.tsv` and `translation/chapter-titles.tsv` — shared decisions, and
  shared with the Norwegian edition. A maintainer folds proposals in between waves.
- `translation/progress.tsv` — generated by `vp run translation:progress`, not written by hand

## Hard rules — these are checked, and a pull request fails without them

Run the checker before opening a pull request:

```bash
vp run edition:check:en-simple
```

- **Every footnote marker in the source appears in the output.** `[^Deming]` in the English
  must survive into the simplified English, and from there into the translation. Footnote
  *definitions* stay as they are — they are bibliography, not prose. Dropping citations is
  the single most common defect in this repo and it is invisible until typesetting.
- **Every figure reference survives.** Keep `figs/…` image paths and their `alt` text; the
  alt text may be simplified, the path never changes.
- **Cross-chapter links resolve.** Links to `https://www.plurality.net/v/chapters/<id>/…`
  must point at a chapter id that exists in `translation/chapter-titles.tsv`.
- **Filenames match `contents/english/` exactly.**

## Judgment — not checked, reviewed by a human

### How to simplify

Read `docs/translation/audience.md` once, and your chapter's note under
`docs/translation/audience/`, before you start. This stage adapts the text to the reader's
education, vocabulary and field of experience — everything except her language.

Work paragraph by paragraph. Keep the paragraph structure: one source paragraph becomes one
output paragraph, so the stages stay alignable.

- Break long sentences into shorter ones. One idea per paragraph (R7).
- Plain words in place of academic register. Keep technical vocabulary a serious newspaper
  already uses (R3) — simplify toward everyday English, never toward another profession's.
- Explain the phenomenon before naming it (R1), and place every unfamiliar person in one
  line at first mention (R4). **Only this stage can do R1 and R4**: a translation branch may
  not add content, so a term left unexplained here is never explained.
- Cut hedging and academic filler. Keep every argument, example, name and number.
- Do not add what the source does not claim. Writing out an assumption is adaptation;
  adding a fact is editing, and it belongs to the editor.
- Expect roughly the source length — the checker expects 85–120%. Much shorter means
  content was lost rather than tightened.

## The editor

Simplifying is a per-chapter job. Editing is not: the editor is the one role that holds the
whole edition at once, and the only one that may change what the book sounds like rather
than what a single chapter says. An editor reviews this edition before it is published, and
their changes are ordinary reviewed commits on this branch like anyone else's.

### What the editor decides

- **The register.** Rules R1–R9 in `docs/translation/audience.md`, and which stage each one
  binds. They are editorial judgment, not checked by the validator.
- **Shared terminology.** The editor folds `translation/proposals/*.tsv` into
  `translation/glossary.tsv` between waves, and is the only role that may edit the glossary
  or `translation/chapter-titles.tsv`.
- **Whether a recurring note has become a rule.** When the same guidance appears in many
  chapter notes, it should move into this file and become checkable.

### What the editor must not do

- **Change `contents/english/`.** Upstream text; fixes go to the upstream repository.
- **Soften the argument.** The profile governs wording, not substance. A chapter written
  from American premises — health insurance, capitalism — keeps those premises.
- **Domesticate institutions.** Taiwan's moda does not become a ministry the reader knows,
  US health insurance does not become her country's system, g0v does not become a local
  volunteering tradition.
- **Break terminology back to the field.** A programmer or democracy activist must still
  recognise the term. Simplify toward everyday English, never toward another profession's
  vocabulary — a word only lawyers and economists share is a failure, not a simplification.
- **Edit a chapter under a contributor's name.** Disagreement goes in review on the
  chapter's pull request.

## Branches

`main` mirrors `upstream/main` exactly and never takes a fork commit.

The two editions have a working branch each, and both are real branches that people commit
to. This branch, `simplify`, carries the simplified English. `norwegian` carries that plus
the translation, and merges this branch to pick up simplified English that is new or has
been edited.

Work flows one way, `simplify` into `norwegian`, and never back — merging the other
direction would bring `contents/norwegian/` onto this branch, which its edition does not
have. So **a change to anything both editions share — tooling, tests, registries, CI, these
instructions, the audience profile — belongs here**, on this branch, and reaches the
Norwegian edition by merge. Made on `norwegian`, it is stranded there.

Run `vp run setup:git` once per clone. `ReadMe.md` and `AGENTS.md` differ per edition on
purpose and are marked `merge=ours` so they stop conflicting on every merge, and git only
honours that once the driver is enabled.

## Building this edition

```bash
vp run edition:check:en-simple
```

Validates this edition's stage and assembles its manuscript into
`dist/publication/en-simple/`. It is assembled while still partial — a chapter joins as it
is simplified — so it can be read long before the last one lands.

Two things on this branch are shared with the Norwegian edition and will look out of place:
`translation/chapter-titles.tsv` carries a Norwegian title for every chapter, and
`translation/glossary.tsv` a Norwegian term for many. Nothing here reads those columns. The
glossary matters on this branch because its English side is the terminology this edition is
expected to preserve.

## Working without repository access

Contributors using a chat-only assistant can copy a ready-made prompt from
`docs/translation/prompts/simplify.md`, paste it together with the chapter text and the
relevant slice of the glossary, and paste the result back into the correct file. The checker
enforces the same rules either way.
